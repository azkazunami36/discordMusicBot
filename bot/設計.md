# どんな設計かを大雑把に箇条書き
- Discord.js
    - VC入室時処理
    - VC退出時処理
    - コマンド受付処理
        - playコマンド
            - 概要: URLを指定して再生。URLを指定しないとキューから再生。再生中にURLを指定しないと次の曲。再生中にURLを指定すると追加。文字列も可能。検索される。
        - stopコマンド
            - 概要: 再生を停止する。退出する時もあれば、しない時もある(VCを録音する必要がある場合に。pauseは利用できない。)。再生していないのにstopを行うと接続状態・再生状態の完全リセットができる(録画中の場合中断されるが、再入室する)。
        - delコマンド
            - 概要: 番号を指定して削除。番号を指定しないと再生中の場合は次の曲が削除される。１曲リピートの場合に限り再生中の曲が消える。
        - clearコマンド
            - 概要: キューをクリアする。
        - settingコマンド
            - 概要: 特殊設定はここから。機能概要を以下箇条書き。
                - チャンネルIDが必要な設定項目(チャンネルID欄を空にすると無効化)
                    - 次の曲を再生したときに通知するか
                    - 特定チャンネルにURLが送られたら再生するか
                    - botを呼び出せるチャンネルを限定するか
                    - 音声を収録し、特定のチャンネルに保存するか
                - オンオフを切り替えるだけの設定項目
                    - 退出時にキューをリセットするか
                    - 退出時にイコライザをリセットするか
        - statusコマンド
            - 概要: キュー一覧が見れる。ページ変更も可能。エクスポートで全ての曲がURLの一覧となる(ページ範囲を指定できる)
        - reverbコマンド・repeatコマンド・speedコマンド・pitchコマンド・seekコマンド・volumeコマンド
            - 概要: プレイヤークラスに送信して状態を変えるだけ。
                - speed・seekコマンドに限りユーザー再生状況監視クラスに情報を送信する。
        - resetコマンド
            - 概要: リピート状態などの簡易的な設定を削除する。allをするとサーバー環境設定などもリセットされる。
- playerクラス
    - 概要: Discord.jsに関わらず全てのユーザーの再生状況を管理する。クラスを通じて再生デバイスの変更やシーク、再生状況の追跡などができるようにする。その上でクラスを複数交えたツールとする。
    - 再生状態をかえる機能
        - 概要: 基本的にこの機能一覧は固定なため、APIでも単純な実装で。
        - play
            - デバイスタイプを入力する。オプションでデバイス名と機種情報を入力する。IDが返ってくる。
        - pause
        - stop
            - IDを入力する。デバイスが解放される。何度実行しても良いので、積極的に解放する。
        - repeat切り替え
        - speed切り替え
        - equalizer
            - 特定周波数と範囲、歪ませる方向、ハイパス・ローパス
            - 31バンド
        - pitch切り替え
        - エフェクト(決まった機能のみ)
            - リバーブ(畳み込み系)
        - 再生位置変更
        - volume切り替え
        - 再生ソース
            - 再生サービス(YouTube、Twitter、ニコニコ動画、SoundCloud、URL、Miharu Music、アップロードされたファイル)
            - 識別ID
            - 存在する場合、ソース番号(Twitterなどの場合に存在する)
    - 再生先
        - 概要: IDで再生先を指定すればいい。Discord.jsは0番、他のデバイスは接続順に。5分以上再生中断状態または再生中の楽曲が２回ループしてもなお他の操作がされない、１時間以上再生アクティビティが更新されない(ループ再生などが行われた形跡がない)場合、デバイスが削除される。playやstopでデバイス識別のためのデータの形式を箇条書き。
            - ID
            - デバイス名(ログインされている場合は識別される)
            - 機種情報またはブラウザ情報(識別ヒント)
        - Discord.js
        - ブラウザ・認識しているデバイス
    - Discord.js再生管理クラス
        - リピート管理
    - ユーザー再生状況監視クラス(アクティビティ管理クラス)
        - 概要: 空っぽのクラスを実装する。実際にどう動くかは決めない。依存先としてミュージックライブラリ(データベースマネージャー)があるが、その程度。クラスを初期化するときにミュージックライブラリにアクセスするためのクラスを引数に入れてあげて。
        - ユーザー再生開始
            - 曲ID
            - 再生開始位置
            - 再生速度
            - 無駄になってもいいからその時の情報(サーバーID、チャンネルID、再生状況など)
        - ユーザー再生終了
            - 曲ID
            - 再生終了位置
            - 再生速度
            - 無駄になってもいいからその時の情報(サーバーID、チャンネルID、再生状況など)
            - 最後まで再生した場合はこれを呼び出さないでもいいし呼び出してもいい。どちらにせよ同じ。
